# Error & support voice · Hexcoded · L24 lock

> Voice **A · Direct & minimal** for v1. Evolve toward Voice E (hybrid) post-launch.

## The pattern

Every error follows: **what happened** (concrete) → **what to do** (action). No filler. No exclamation marks. No "Oops!".

## Locked v1 samples

| Error scenario | Copy |
|----------------|------|
| Generation failed | Couldn't generate. Try again. |
| Network timeout | Slow connection. Retrying in 10s. |
| Out of credits | Out of credits. Add more to continue. |
| Server error 500 | Something broke on our side. We're on it. |

## Rules

- Lead with the diagnosis, not the apology.
- Use simple past tense for the failure ("Couldn't…").
- Use imperative or simple future for the next action ("Try again.", "Retrying in 10s.").
- No "Oops!", no "Whoops!", no "We're so sorry…", no exclamation marks.
- Never blame the user. Blame the system or describe the state neutrally.
- Maximum two short sentences. If you need more, you're explaining — link to docs instead.

## Post-launch · Voice E hybrid

Once we have data on which surfaces users hit most, layer:

- **Voice A** (direct) for system errors (timeouts, 5xx, connection drops).
- **Voice B** (brand verb) for product feedback ("Didn't quite hexcode. Try again.").
- **Voice C** (playful) only on community surfaces (status page, footer, beta opt-in).
- **Voice D** (empathetic) for paid-plan / enterprise errors ("Sorry about that — we're working on it now.").
