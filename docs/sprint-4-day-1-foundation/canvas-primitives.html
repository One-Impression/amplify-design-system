2. Toast (Ephemeral Notification)

canvas.toast

Dark-base toast with severity left-bar. Four variants. Extracted from: Oportunities creator-app .toast (dark ink bg + accent emoji + light text — proven legibility). Severity bar added for Canvas to cover info/warning/danger uses across products.

Behavior
  • Auto-dismiss: success 4s · info 4s · warning 6s · danger 8s
  • Action toasts persist until tapped/dismissed (no auto-dismiss when action set)
  • Stack max 3 visible; oldest dismisses first; 8px vertical gap
  • Mobile: bottom-center, slide-up 200ms ease-out. Desktop (≥768px): top-right, slide-left 200ms ease-out.
Tokens used

--canvas-ink · --canvas-success · --canvas-info · --canvas-warning · --canvas-danger · --canvas-radius-lg · --canvas-shadow-lg

A11y: Container has role="status" + aria-live="polite". Danger/warning use aria-live="assertive". Action button gets focus when present. Dismiss button has aria-label="Dismiss". Respect prefers-reduced-motion by skipping slide animation.

3. Inline Form Error

canvas.inline-error

Field-level error message with two severities. Gentle (warm-accent, PAT-OPT-001 — the default for almost everything) and strict (only when the input is truly invalid, e.g., wrong email format). Extracted from: PAT-OPT-001 (Oportunities patterns.md) — "soft language, no scary framing".

Gentle (default — PAT-OPT-001)

Props API
PropTypeDefaultNotes
severity'gentle' | 'strict''gentle'Default to gentle (PAT-OPT-001)
messagestring—Required
fieldIdstring—For aria-describedby wiring
withIconbooleantrueShow leading icon
Behavior
  • Default to gentle. Choose strict only when the user literally can't continue (DPDP-required field empty, format actually wrong).
  • Strict variant shake animation fires only on submit-attempt error, not on initial mount (200ms horizontal jitter).
  • Helper text (if present) hidden when error shows.
  • Field border bumps to 1.5px in severity color when error present.
Tokens used

--canvas-gentle · --canvas-danger · --canvas-radius-md

A11y: role="alert" + aria-describedby="{fieldId}". Live region announces on appear. Color is reinforced by icon (don't rely on color alone — WCAG 1.4.1).

4. Share / Copy CTA

canvas.share-cta

Text-button with leading icon for share/copy interactions. Three variants: share (native Web Share API), copy (clipboard), share-with-copy-fallback (share first, copy if unsupported). Extracted from: Oportunities .bc-copy (copy-email pattern) + P-01 invite-share.

Default state — all 3 variants
Success state (after tap — 1.2s, then revert)
Icon-only variant
Props API
PropTypeDefaultNotes
variant'share' | 'copy' | 'share-with-copy-fallback'—Required
payloadSharePayload—{ title, text?, url?, files? } (Web Share API shape)
labelstring'Share' | 'Copy link'Default depends on variant
successLabelstring'Shared!' | 'Copied!'Shown for 1.2s after action
iconOnlybooleanfalseHide label; requires aria-label
onShared() => void—Fired on share-sheet completion
onCopied() => void—Fired on clipboard write
Behavior
  • On success: icon morphs to ✓ + label changes to successLabel for 1.2s, then reverts.
  • share uses navigator.share(payload); falls back to no-op if unsupported.
  • copy writes payload.url ?? payload.text via navigator.clipboard.writeText() with document.execCommand('copy') legacy fallback.
  • share-with-copy-fallback tries navigator.share; if unavailable, copies the link to clipboard + triggers success toast.
  • Pair with Toast primitive (variant: success) for action confirmation when needed.
Tokens used

--canvas-ink · --canvas-ink-2 · --canvas-bg-soft · --canvas-success · --canvas-radius-md

A11y: Native button element with full keyboard support. icon-only requires aria-label. Success state announces via aria-live="polite" on the label span. Focus ring inherited from button default.
